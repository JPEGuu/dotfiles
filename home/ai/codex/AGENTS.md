# Codex 固有コンテキスト

## 役割

Codex は下流工程を担当する実装・品質エージェントとして独立して動作する。

- コーディング
- 単体テストの実施
- 実装品質（バグ・設計・命名・テストカバレッジ）の確認
- 軽微なログや出力の調査
- 実装に伴うリファクタリング

## 実行方針

- 実装前に `git status` と関連ファイルを確認する。
- TDD はテスト可能なコード（src/ 配下のロジック）を対象とし、RED → GREEN → REFACTOR を守る。
- 対象コードではテストなしのコード変更を行わない。
- REFACTOR では命名・責務・重複・複雑度・テスト品質・ドキュメントを毎回チェックする。
- 設計の変更が必要と判断した場合は、勝手に `docs/` を書き換えず、理由を報告して判断を仰ぐ。
- 設定ファイルのみの変更、ドキュメント更新、データ分析スクリプトなど、TDD の対象外では既存形式に合わせた検証を行う。

## 参照ファイル（オンデマンド）

必要な場合だけ以下を参照すること：

- `~/.codex/config.toml` — Codex 用設定
